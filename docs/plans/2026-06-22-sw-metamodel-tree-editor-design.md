# SystemWeaver 元模型结构树编辑器 — 设计文档

- 日期：2026-06-22
- 状态：已确认，待实现
- 类型：全新工具（greenfield）

## 1. 背景与目的

在 SystemWeaver 扩展开发中，常需要给 AI 提供一段**元模型结构图**（ItemType 之间通过 PartType 连接的树），帮助 AI 理解项目的结构。格式示例：

```
Mapping Tree (IMT01)
├─[PPT01]→ Polarion Tree (IPT02)
│   ├─[PSP06]→ Space (ISA03)
│   │   ├─[PSP05]→ Space (ISA03)
│   │   │   └─[PPD02]→ Doc (IPD02)
│   │   │       └─[PPW01]→ Requirement
```

语义：`Name (ItemType SID)` 是节点；`[PartType SID]→` 是连到父节点的边（对应 sw-ext-dev 的 Part/PartType 概念）。

**痛点**：AI 生成的这类树文本常有小差错（缩进、连接符 `├─└─│`、SID 配错、连接符不一致）。手动对齐这些 Unicode 树形字符很折磨。

**目标**：做一个工具，把"对齐字符"变成"操作节点"——导入文本 → 可视化编辑 → 导出规范文本/复制。

## 2. 关键决策（已确认）

| 维度 | 决策 | 理由 |
|---|---|---|
| 运行形态 | 单个 HTML 文件 | 双击即开、零安装、零服务器、可离线、随身拷贝 |
| 编辑交互 | 缩进列表 + 按钮（上/下/左/右/增/删/编辑） | 稳健、不易出错、够用 |
| 持久化 | 单棵树 + localStorage 自动存储 | 符合"一次一棵"工作流；防误刷新丢失 |
| 格式策略 | 导入容错 + 导出严格规范 | 输入什么变体都能改，输出一定干净 |
| 实现方式 | 纯原生 HTML/CSS/JS，零依赖 | 真·单文件可离线、体积小、永不依赖网络 |
| 连接符规则 | 标准 ASCII 树规则（见 §6） | 统一规范、无歧义、AI 读取更稳定 |

## 3. 数据模型

一棵树。每个节点：

```js
node = {
  name: string,        // "Mapping Tree"、"Space"、"Requirement"
  itemSid: string|null,// "IMT01"、"ISA03"；可空（如叶子 "Requirement"）
  partSid: string|null,// "PPT01"；仅根节点为 null
  children: [node]     // 有序子节点数组
}
```

### 不变量

- **根节点的 `partSid` 为 null**；其余所有节点必有 `partSid`
- `itemSid` 任意节点都可空（包括根，尽管根通常有）
- `partSid` 语义挂在"指向父节点的那条边"上（= SystemWeaver PartType SID）
- `itemSid` 语义是本节点自身的类型（= SystemWeaver ItemType SID）

### 合法性说明

- **同一 ItemType 可在多处出现**（如示例中 `Space (ISA03)` 出现两次，表示同一类型在不同位置被引用/共享实例）。因此**不**做 SID 唯一性校验。

## 4. UI 布局（单页三区）

```
┌─────────────────────────────────────────────┐
│ [导入文本框]          [导入] [清空]          │  顶部：导入区
├─────────────────────────────────────────────┤
│  树编辑区（缩进列表）                         │
│  每行：缩进 + [PartSID]→ Name (ItemSID)     │
│  行尾按钮：↑ ↓ ← → ＋ ✎ ×                    │  中部：编辑区
├─────────────────────────────────────────────┤
│  规范化输出（只读预览）  [复制] [下载.txt]    │  底部：输出区
└─────────────────────────────────────────────┘
```

### 节点行操作按钮

| 按钮 | 含义 | 约束 |
|---|---|---|
| `↑` / `↓` | 在兄弟间上移/下移 | 已是首/末兄弟时禁用 |
| `→` | 缩进：变成"前一兄弟"的子节点 | 没有前一兄弟时禁用（根节点禁用） |
| `←` | 提升缩进：变成"父节点"的兄弟 | 根节点或父是根时禁用 |
| `＋` | 添加子节点（在末尾追加空节点） | — |
| `✎` | 进入本行字段编辑（partSid/name/itemSid） | — |
| `×` | 删除本节点及其整个子树 | 根节点删除 = 确认后清空整树 |

### 字段编辑

`partSid`、`name`、`itemSid` 点击即原地可编辑（contenteditable 或 inline input）。根节点不显示 `partSid` 字段（无入边）。

## 5. 容错解析器（核心算法）

逐行处理，跳过空行。对每行：

1. **剥离树前缀**：扫描并吃掉前导的"树字符"`[ \t│|├└┌┐┘─\-+\\/]`（含混合），记录内容起始列号 `col`。
2. **确定父节点**：用"最近一条 `col` 严格小于本行的行 = 父节点"（标准缩进父查找法），深度 = 父深度 + 1；第一条非空行 = 根（深度 0）。
3. **提取字段**：剥离后对剩余内容用正则解析：
   ```
   可选 [PARTSID]  +  可选 箭头(→/->/>)  +  Name  +  可选 (ITEMSID)
   ```
   - 根节点无 `[PARTSID]` → `partSid = null`
   - 无 `(ITEMSID)` → `itemSid = null`

### 兼容的 AI 变体

- box-drawing 字符（`├─└─│`）与 `+--`、`|--`、`/`、`\` 等混合
- 纯空格缩进（2 空格 / 4 空格 / Tab 混用）
- 箭头写作 `→`、`->`、`>` 或缺失
- 多余空格、空行
- 缺失 `[PartSID]` 或 `(ItemSID)`

### 父查找法为什么鲁棒

不依赖固定缩进单位（4 空格/2 空格/Tab），只依赖"内容起始列号"的相对大小关系。无论 AI 用什么缩进风格，只要同一棵树内缩进一致，就能正确还原层级。

## 6. 严格序列化器（规范输出）

### 连接符规则（标准 ASCII 树）

- 节点是父节点的**最后一个孩子** → 用 `└─`；否则 → `├─`
- 祖先链延续前缀：该祖先**还有后续兄弟**用 `│   `（竖线 + 3 空格），否则用 `    `（4 空格）
- 根节点：无前缀、无连接符，直接 `Name (ItemSID)`

### 行格式

- 根：`{name}` +（有 itemSid）` ({itemSid})`
- 非根：`{前缀}{连接符}[{partSid}]→ {name}` +（有 itemSid）` ({itemSid})`
  - 其中 `→` 后有 1 个空格，`[` 紧贴连接符无空格

### 示例

输入示例规范化后（所有节点均为独子，故全 `└─`）：

```
Mapping Tree (IMT01)
└─[PPT01]→ Polarion Tree (IPT02)
    └─[PSP06]→ Space (ISA03)
        └─[PSP05]→ Space (ISA03)
            └─[PPD02]→ Doc (IPD02)
                └─[PPW01]→ Requirement
```

## 7. 轻量校验（不阻塞，仅提示）

| 情况 | 表现 | 处理 |
|---|---|---|
| 解析失败的行 | 红色高亮 + 保留原文 | 用户在导入框或编辑区修 |
| 非根节点缺 `partSid` | 黄色警告 | 边没有 PartType SID，语义不完整 |
| 重复 ItemType SID | **不报** | 合法场景（共享实例） |

## 8. 持久化

- 存储：`localStorage` 单键（如 `sw-tree-editor:v1`），值为整棵树的 JSON
- 时机：每次树改动后自动写入
- 恢复：页面加载时若存在存储则自动还原
- 导入新文本：覆盖当前树，**弹确认**（避免误丢工作）

## 9. 文件结构

单文件 `index.html`，内部按逻辑分区（不拆物理文件）：

```html
<!DOCTYPE html>
<html>
<head> <style>/* 全部样式 */</style> </head>
<body>
  <!-- 导入区 / 编辑区 / 输出区 -->
  <script>
    // 1. 数据模型 + state
    // 2. 解析器 parseTree(text) -> {root, errors}
    // 3. 序列化器 serializeTree(root) -> string
    // 4. 渲染 render(root)
    // 5. 操作 handlers（移动/增删/编辑）
    // 6. localStorage 存取
    // 7. 导入/复制/下载 handlers
  </script>
</body>
</html>
```

## 10. 非目标（YAGNI）

明确**不做**：
- 多树管理 / 命名 / 列表
- 元模型 SID 词典或自动补全（项目特定，不属于本工具）
- 与 SystemWeaver 服务器集成
- 拖拽重排（按钮已够用）
- 框架/构建系统（保持零依赖单文件）
- 强制 SID 格式校验（只做缺失提示）

## 11. 验收标准

1. 粘贴示例文本能正确还原为可编辑树（层级、各 SID 正确）
2. 粘贴带变体（`+--`、2 空格缩进、`->`、空行）也能正确还原
3. 所有按钮操作（移动/缩进/增/删/编辑）行为正确且不破坏不变量
4. 刷新页面后树仍在
5. 复制/下载的输出严格符合 §6 规范（连接符、缩进、字段顺序）
6. 非根缺 partSid 时有黄色提示；解析失败行有红色提示
7. 整个工具是单个 `index.html`，断网双击可用，无任何外部依赖
